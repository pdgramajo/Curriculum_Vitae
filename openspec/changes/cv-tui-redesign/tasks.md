### Phase ordering rationale

F0 must exist before anything (rollback anchor). F1 installs pytest and the fixtures every later test uses. F2a (discovery) precedes F2b (rendering) because `RenderingService.render` takes a `CVSource`; F3 (CLI) needs both; F4 (TUI) delegates to discovery/rendering and to `cli.run_tui`; F5 switches the launchers only after every headless path passed — that is the proposal's rollback plan: build alongside, switch in one commit, then remove.

### Threat-matrix propagation

Applicable rows from the design's threat matrix become explicit RED tests BEFORE their production code: **subprocess invocation** (argv with spaces → 2.4; missing executable → 2.6; timeout → 2.6; cleanup scoping/photo survival → 2.5; `shell=True` scan → 2.9) and **executable/launcher env** (launcher from foreign cwd → 5.4; missing `.venv` → 5.4; `.command` pause → 5.10). Rows marked N/A in the design (docs-like paths, git/commit/push/PR automation) stay omitted — the app runs no git commands.
